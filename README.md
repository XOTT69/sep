# SEP Analyzer

Внутрішній інструмент для аналізу історії міжбанківських платежів СЕП за UETR.

## Поточний стан

Перший MVP — клієнтський аналізатор:
- введення UETR та суми;
- перевірка формату UETR;
- імпорт XML-повідомлень ISO 20022 (зокрема trck.002 та pacs.004) або вставлення XML;
- побудова хронології статусів;
- витягування кодів і тексту причин повернення з pacs.004;
- пояснення відомих кодів причин із позначенням, що це довідкова інтерпретація;
- посилання на офіційний ТрекСЕП.

## Важливе обмеження інтеграції

Публічний вебзастосунок ТрекСЕП наразі не надає підтвердженого відкритого HTTP API для браузерного стороннього клієнта. Документація НБУ описує обмін учасника ТрекСЕП із ЦОСЕП повідомленнями trck.999/trck.002. Тому MVP не обходить авторизацію, CAPTCHA чи інші механізми захисту і не заявляє про автоматичне отримання даних із сайту НБУ.

Щоб додати автоматичне отримання, потрібен офіційно дозволений API/інтеграційний канал або погоджений експорт даних. До цього часу дані імпортуються з XML, отриманого законним способом, або перевіряються вручну в офіційному сервісі.

## Запуск

Це статичний застосунок. Відкрийте `index.html` у браузері або розгорніть репозиторій на Cloudflare Pages / GitHub Pages.

Жодні введені дані не надсилаються на сторонній сервер: обробка XML відбувається локально в браузері.

## Швидкий сценарій пошуку

Застосунок відкриває офіційний ТрекСЕП і копіює UETR та суму для вставлення у форму НБУ. Після вибору «Повна відповідь» користувач може скопіювати таблицю історії та вставити її в SEP Analyzer для локального розбору.

## Обмеження автоматизації

Функціональний опис НБУ (версія 1.2 від 25.02.2026) описує відкриту WEB-сторінку для ручного запиту UETR + сума та програмний обмін через учасника ТрекСЕП. Публічний сторонній API для довільного застосунку в документації не описаний. Тому застосунок не звертається до прихованих endpoint і не обходить захист сайту. Для повністю автоматичного отримання потрібен офіційно дозволений API/інтеграційний канал або погоджений доступ учасника.
